# Releasing BizBill

## One-time: create the production signing key

The same key must sign **every** future release. If it is lost, installed
apps can never be updated (users would have to uninstall, losing local data
unless they restore a backup). Keep two offline copies (e.g. password manager
plus an encrypted USB drive).

```bash
keytool -genkeypair -v -keystore bizbill-release.jks -alias bizbill \
  -keyalg RSA -keysize 4096 -validity 10000 \
  -dname "CN=BizBill, O=BB MFG, C=IN"
# Fingerprint to pin in CI:
keytool -list -v -keystore bizbill-release.jks -alias bizbill | grep SHA256
```

Never commit the keystore or passwords (`*.jks`, `*.keystore` are git-ignored).

## One-time: GitHub secrets

Repository → Settings → Secrets and variables → Actions:

| Secret | Value |
|---|---|
| `BIZBILL_KEYSTORE_BASE64` | `base64 -w0 bizbill-release.jks` |
| `BIZBILL_KEYSTORE_PASSWORD` | keystore password |
| `BIZBILL_KEY_ALIAS` | `bizbill` |
| `BIZBILL_KEY_PASSWORD` | key password |
| `BIZBILL_CERT_SHA256` | the SHA-256 fingerprint without colons (optional but recommended: CI fails if a different key is ever used) |

Secrets are only used by the release build step and are never printed.

> If a BizBill APK was already distributed with another key, that key must be
> used here, otherwise Android will refuse to install updates over it.

## Versioning

`version.properties` is the single source of truth:

```
VERSION_NAME=3.5        # shown to users; tag must be v3.5
VERSION_CODE=13         # must increase for EVERY release
MIN_SUPPORTED_VERSION=3.0
MANDATORY_UPDATE=false  # true = security update, users must update
```

Before the first release set `VERSION_NAME` / `VERSION_CODE` above the values
of any BizBill APK already installed on users' phones.

CI refuses to build when:
- `www/js/version.js` is out of sync (`npm run version:sync`),
- `VERSION_CODE` is not **greater** than the newest published `update.json`,
- the tag is not `v<VERSION_NAME>` or the release already exists,
- the signing certificate differs from `BIZBILL_CERT_SHA256`.

## Making a release

1. Update `version.properties` (increase both values) and run `npm run version:sync`.
2. Add a `## <version>` section at the top of `RELEASE_NOTES.md`.
3. Commit, then tag and push:
   ```bash
   git tag v3.6 && git push origin v3.6
   ```
   (or run the workflow manually with **release = true**; tick **mandatory**
   for a security update).
4. GitHub Actions: tests → lint → versionCode check → `assembleRelease` +
   `bundleRelease` (signed, R8) → signature verification → SHA-256 →
   `update.json` → GitHub Release with:
   - `BizBill-release.apk` (direct install / in-app update)
   - `BizBill-release.aab` (Play Store)
   - `checksums.txt`, `update.json`, `release-notes.md`
5. Installed apps check `…/releases/latest/download/update.json` when online
   (at most every 6 hours, and when connectivity returns) and offer the update.

## update.json

```json
{
  "packageName": "tech.bbmfg.bizbill",
  "latestVersionName": "3.6",
  "latestVersionCode": 14,
  "downloadUrl": "https://github.com/arifmemon916-creator/bb-mfg/releases/download/v3.6/BizBill-release.apk",
  "sha256": "<64 hex characters>",
  "mandatoryUpdate": false,
  "minimumSupportedVersion": "3.0",
  "releaseNotes": "…"
}
```

It is generated by `tools/make-update-json.mjs` and validated in CI with the
same rules the app uses (`tools/validate-update-json.mjs`). The app verifies
package name, version code, SHA-256 and signing certificate before handing the
APK to Android's installer.
